## 一个演示故事

讲解“提交笔记并不等于学会：系统依据固定提交生成报告，再用追问验证理解，全部必需标准满足才解锁下一任务”。以下 2 至 4 分钟路线仅供面试介绍参考，不要求录制或额外组织一轮演示验收，时间也不是模型延迟指标。

| 建议时间 | 页面与操作 | 需要讲清的事实 |
| --- | --- | --- |
| 0:00–0:30 | 学习计划，查看当前任务与目标路径 | 计划有依赖关系，笔记需写到绑定仓库的指定路径 |
| 0:30–1:10 | 展示一次已取证 Push 的提交与对应笔记报告 | 验收读取固定 SHA，不随仓库后来变化；“已取证”还不代表任务通过 |
| 1:10–1:50 | 展开一个验收项，定位引用，查看固定正文或 Diff | 结构检查与语义判断分工，引用可定位也不保证判断正确 |
| 1:50–2:40 | 切换“追问回答”，展示已保存的回答报告 | 回答有独立 Run；Run 成功与回答通过是不同结论 |
| 2:40–3:20 | 回到计划，展示 Task 通过及后继解锁；刷新后查看同一结果 | 页面从持久化状态恢复，全部前置通过才解锁 |
| 3:20–4:00 | 简述断网恢复、幂等和已知评分限制 | 可靠性证据与模型效果证据分开，不声称零故障或模型永远正确 |

若面试时展示已有结果，明确说“这是此前执行并保存的报告”。若现场运行未完成，就展示等待/失败与恢复，不把旧报告说成本次结果。使用自己授权的材料，不展示 Cookie、密钥、真实私人笔记与无关账号信息。

## 面向前端实习的简历初稿

以下只描述已实现职责，不写未经测量的收益；个人署名时应能解释自己的实现、手写与 AI 辅助部分。

> **KnowledgeOps Agent｜GitHub 驱动的学习验收工具**
>
> 技术栈：Nuxt / Vue 3、TypeScript、TanStack Query、NestJS、Prisma、PostgreSQL、BullMQ、LangChain、Docker、GitHub Actions。
>
> - 构建计划与验收工作台，使用 URL 保存任务、报告和页签选择，支持固定提交正文、Diff 与引用定位，以及追问回答和关联重试。
> - 实现计划生成 SSE 快照恢复，结合版本/批次隔离、HTTP 校准和轮询兜底处理刷新、断网及旧通知；回答命令保留 requestId，配合后端幂等避免响应丢失后的重复创建。
> - 打通 GitHub Push → 固定提交取证 → 笔记/回答验收 → Task 通过与依赖解锁，使用 Outbox、数据库版本复核与事务保存保护异步结果。
> - 使用 Playwright 覆盖学习闭环、会话隔离与故障恢复；通过 GitHub Actions 完成测试、镜像验证及 GHCR 发布，支持手动选版部署与兼容版本回退。
