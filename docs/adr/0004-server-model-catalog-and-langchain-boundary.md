# ADR 0004：服务端模型目录与 LangChain 适配边界

- 状态：Accepted
- 日期：2026-08-08

## 背景

计划生成需要调用大模型，但 9 月版本的首要目标是形成可解释、可恢复的产品闭环。若让浏览器提交 API Key、任意模型名或 Base URL，安全边界、供应商兼容性、错误排查和成本控制都会显著扩大。若同时让 LangChain 接管业务状态、重试和持久化，系统还会出现与 PostgreSQL 重叠的真相源。

## 决策

部署方通过服务端环境变量配置一个模型供应商、凭据和 1 至 2 个允许模型。API 对浏览器只公布稳定模型 ID 与展示信息，用户只能选择目录内的 ID；服务端将 ID 映射为真实供应商配置，API Key 不进入客户端、数据库、日志或错误响应。

计划生成在当前阶段使用带严格超时的同步调用。LangChain 只位于模型适配器内，负责标准模型接口、供应商集成和 Zod 结构化输出；应用服务、事务、计划数量与日期校验、DAG 规则和状态迁移由项目代码掌握。共享 Contracts 和 Prisma 模型不依赖 LangChain 类型，PostgreSQL 继续作为业务真相源。

模型未配置、超时、供应商失败或结构化输出非法时，系统保留已经创建的 LearningGoal，返回明确且可重试的错误，不创建半份 Plan，也不静默切换模型或用规则/Mock 结果降级。测试 Fake 与生产模型实现共享项目定义的端口，但 Fake 不能成为生产 fallback。

Plan 保存实际使用的供应商、模型、Prompt 版本和输出 Schema 版本快照；之后修改用户模型偏好不能改写历史记录。

## 结果

- 模型密钥和供应商细节留在可信服务端，客户端输入面和泄密风险更小。
- 用户仍能选择模型，历史 Plan 也可以解释由哪个版本生成。
- LangChain 可以替换供应商 SDK 的重复接入代码，但不会成为第二套业务工作流或恢复系统。
- 同步生成实现更短、演示链路更直观，但 API 必须设置严格超时，且一次请求会占用一个在途连接。
- 不提供降级会降低模型故障时的可用性，但避免把 Mock 或规则计划伪装成真实模型结果。

## 放弃的方案

- 用户自带 API Key：P0 会额外承担密钥加密、轮换、供应商配置校验、隐私说明和支持成本。
- 浏览器直连模型供应商：会暴露密钥，也无法集中执行白名单、超时、审计与错误映射。
- 自动切换模型或规则降级：结果来源不透明，难以复现并会污染产品效果数据。
- 使用 LangGraph Checkpointer/Memory 管理计划生成：当前是一次有界调用，额外持久化会与 PostgreSQL 业务状态重叠。
- 现在引入 BullMQ/Outbox：计划生成尚不需要后台恢复语义，异步可靠链路留到阶段 3 按真实需求实现。
