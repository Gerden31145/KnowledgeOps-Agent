# 阶段 1 历史每日手写：Task 状态迁移

## 任务边界

- 计划日：原定 08-05，由用户在 08-04 提前完成并通过 Review
- 分类：2026-08-06 双层手写规则生效前的约 30 分钟练习；保留为历史每日手写，不抵扣阶段 1 新增的 1 至 2 小时核心手写
- 实现文件：`packages/contracts/src/domain/task-state.ts`
- 函数签名：`isValidTaskTransition(from: TaskState, to: TaskState): boolean`
- 时间上限：20 至 30 分钟
- 只修改函数实现；不要改状态常量或验收测试来让测试通过。

## 输入、输出与不变量

- 输入是已经过 `taskStateSchema` 校验的两个内部状态。
- 只允许测试中列出的直接迁移；不能跳过中间业务状态。
- 相同状态不是一次迁移，必须返回 `false`。
- `PASSED` 是终态，不能再迁出。
- `VERIFYING → IN_PROGRESS` 是技术运行失败时回到旧稳定状态的显式恢复路径。
- 函数必须是纯函数：不修改外部数据，不读时间、网络或数据库，对合法类型输入不抛异常。

这个函数只判断状态图中是否存在一条边，不负责判断“当前 Worker 是否仍有权更新这条 Task”。后续持久化代码仍必须用预期版本和预期状态做原子条件更新；纯函数不能替代乐观锁。

## 验收用例

专用测试覆盖五类行为：

1. 接受所有明确允许的直接迁移；
2. 拒绝所有自迁移；
3. 拒绝跳过中间状态；
4. 拒绝恢复路径之外的逆向迁移；
5. 保证 `PASSED` 没有出边。

运行命令：

```powershell
pnpm test:handwrite:task-state
```

08-04 交付时该命令会因为 `TODO(user)` 按预期失败。完成实现后应全部通过，再执行：

```powershell
pnpm check
```

专用配置用于在手写期间单独运行这组用例。Review 通过后，`vitest.config.ts` 也会匹配 `*.exercise.ts`，因此状态迁移测试已经进入默认 Vitest 和 CI 回归范围。

## 分层提示

1. 先选择一种能直接表达“某状态允许去哪些状态”的数据结构，不要写一长串互相重复的布尔表达式。
2. 可以用 `Record<TaskState, readonly TaskState[]>`，或 `satisfies` 检查映射是否覆盖了所有状态。
3. 查表后只需判断 `to` 是否存在于当前状态的允许目标集合中；无需修改输入，也无需访问任何外部依赖。
