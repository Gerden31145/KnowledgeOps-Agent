## 接口：三个数不要混淆

| 字段 | 含义 |
| --- | --- |
| `runId` | 当前页面订阅的 Run，不是 Plan ID |
| `epoch` | 本地订阅批次；每次选择/停止产生新批次。即使 A → B → A，最后的 A 也不是第一次 A 的订阅 |
| `snapshot.version` | 数据库中同一 Run 的版本，用于比较两个快照的新旧；不能跨 Run 比较 |
| `refreshKey` | HTTP 校准的触发序号；增加它表示请求一次最新快照，不是数据版本 |
| `snapshot` | 当前认可的完整快照；没有数据时为 `undefined` |
| `issue` | 同步通道问题，与快照中的业务错误 `snapshot.error` 分开 |

`initialRecoveryState()` 已提供。空值用接口规定的 `null` / `undefined`，不要自行换成空对象。普通事件带 `epoch`，由适配器在发起异步操作时记录；`select` / `stop` / `refresh` 是本地生命周期或用户操作。

## 你返回的 mode 会产生什么效果

| mode | 配套代码的行为 |
| --- | --- |
| `idle` | 不持有目标或同步资源 |
| `connecting` | 保留一条 EventSource，最多等待 10 秒连接成功；重复 error 不延后截止时间 |
| `streaming` | 保留 SSE，取消连接等待计时器，不启动周期 HTTP 轮询 |
| `polling` | 关闭 SSE，立即 HTTP 查询，之后每次请求完成再等 2 秒查询；失败也有间隔 |
| `stopped` | 清理订阅、请求和计时器；保留终态结果，或保留需要展示的访问错误 |

`refreshKey` 增加时，活跃模式下会触发 HTTP 查询；已有请求时最多合并成一个后续查询，不叠加无限请求。切换 `epoch` 会撤销旧资源。`snapshot` 引用变化时写 Query 缓存；保持原引用则不重复写。错误停止时将快照清空，会移除对应缓存。

以上由 `plan-run-recovery-driver.ts` 执行；它**不替你判断版本、终态、旧批次或应该选择哪个 mode**。`use-plan-run-recovery.ts` 负责监控 URL 的 Run ID/用户身份、页面卸载、连接 HTTP/SSE/Query，以及鉴权失效后清缓存和回登录页。首轮无需逐行阅读适配器。

## 必须满足的规则

1. **选择与停止**：选择非空 Run 时建立新批次，清除旧错误，只接受属于该 Run 的缓存作为起点，进入 `connecting` 并要求首次 HTTP 校准。没有匹配缓存就清空快照。本题统一先建连校准，即使有缓存也不以它代替本次订阅。`stop` 或选择 `null` 时清空当前 Run/快照/错误，进入 `idle` 并使旧批次失效。
2. **批次隔离**：旧 epoch 的快照、错误、open 和超时通知都不能改变当前状态；仅检查 runId 不足以处理 A → B → A。idle 没有目标时不接受异步消息。
3. **快照一致性**：只接收当前 Run 的快照。没有快照或收到严格更新的版本时接受；旧版本、同版本保留原快照引用。不要无条件复制快照对象。合法同步成功可清除通道错误，但不能因为收到 HTTP 快照就将轮询模式恢复成 SSE 模式。
4. **终态不可覆盖**：以最终保留的快照为准，`SUCCEEDED / FAILED / TIMED_OUT` 都应停止同步。已保存的终态不能被后来的 RUNNING 覆盖，即使传来的版本更大。旧版本的 FAILED 也不能结束当前较新 RUNNING。进入 stopped 后，迟到异步消息、超时和 refresh 不再启动资源；新 select 仍可开始另一次订阅。
5. **open 与手动刷新**：connecting/streaming 下收到当前批次的 opened，表示首次连接或原生重连成功，进入 streaming、清除通道错误，并要求一次 HTTP 校准。活跃模式的 refresh 也要求一次校准。正常 SSE 与周期轮询不长期同时运行。
6. **断线与兜底**：普通 connection 问题先进入 connecting，保留业务快照并要求 HTTP 探测（原生 error 不提供 HTTP 状态）。connecting 收到 fallback-due 后转 polling；明确 unavailable（协议异常、明确流不可用或 HTTP 暂时失败）也转 polling。轮询期间不再处理旧 SSE 的 opened/connection 通知，不自动升级回 SSE；重新选择或刷新页面才重新尝试 SSE，避免引入另一套恢复策略。
7. **失败不改业务状态**：连接/HTTP 暂时失败只记录 issue，保留已有快照，不把 Run 改成 FAILED。轮询请求失败不要反复增加 refreshKey，配套代码会安排下一轮；否则会形成无间隔重试。合法快照到达后清除同步错误，包括同版本的有效恢复响应。
8. **权限失败立即停止**：当前批次的 unauthorized/not-found 清空可见快照、保留错误并 stopped，不能无限重连或轮询。适配器已把 HTTP 401/403、400/404 和明确 SSE 鉴权/归属错误分类；你不用解析 HTTP 或 JSON。注意先前批次的 401 也属于应忽略的旧消息。

不实现：持久化事件日志、Last-Event-ID 重放、模型 Token 流、多 Run 并行面板、自动从轮询升级 SSE、通用状态机库。
